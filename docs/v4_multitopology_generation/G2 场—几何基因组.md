# G2 场—几何基因组升级规划（拟议）

> 统一声明：本文新增的 V2/V5、profile、migration receipt、compiler 和 gate 均为拟议；UP0–UP2 的合同、输入输出、阈值和身份规则必须先冻结，再进入 UP3–UP6。四个版本轴分别是 payload schema version、canonicalization/hash profile version、grammar/capability applicability profile version、execution/evidence receipt version；它们不能互相替代。V1/V4 历史哈希和证据保持不变。

可以把场—几何基因组定义成：

\[ \mathcal G_{\mathrm{FG}} = (\mathcal X,\Phi,\mathcal A,\mathcal Q,\mathcal B, \mathcal E,\Theta) \]

其中：

- \(\mathcal X\)：空间、坐标图与度量；
- \(\Phi\)：材料/区域隐式场；
- \(\mathcal A\)：势函数和物理场；
- \(\mathcal Q\)：外部源分布；
- \(\mathcal B\)：边界与接口算子；
- \(\mathcal E\)：几何演化和拓扑事件；
- \(\Theta\)：有界连续参数。

核心原则是：

> genome 保存连续场的生成程序；网格、曲面、导线、磁轴、磁岛和闭合区都是求解后的 phenotype。

## 1. 空间基因

首先声明场定义在哪里，但不预设装置名称：

```
SpatialSupportGene
├─ ambient_dimension
├─ chart_count
├─ chart_bounds[]
├─ periodic_axes[]
├─ metric_program
├─ coordinate_maps[]
├─ chart_transition_maps[]
└─ resolution_independent_scale
```

例如：

```
{
  "ambient_dimension": 3,
  "chart_count": 1,
  "chart_bounds": [[-4, 4], [-4, 4], [-4, 4]],
  "periodic_axes": [],
  "metric_program": {"opcode": "EUCLIDEAN_METRIC"},
  "reference_length_m": 1.0
}
```

复杂空间可由多个 chart 及其 transition map 描述，而不是强迫使用“环形”或“线性”标签。

## 2. 区域和材料如何编码

不直接生成：

```
plasma region
vacuum region
wall region
```

而是生成若干隐式相场：

\[ \phi_r(x,t) = b_r+ \sum_{j\in A_r} c_{rj}\, \psi_{\tau_j} \left(2^{\ell_j}R_jx-d_j\right) T_{m_j}(t). \]

每个活跃基函数项是一条基因：

```
ImplicitFieldTermGene
├─ field_ref
├─ basis_family
├─ level
├─ spatial_multi_index[]
├─ rotation_or_frame
├─ translation[]
├─ temporal_mode
├─ coefficient_gene
└─ unit_signature
```

可以使用：

- Fourier；
- B-spline；
- wavelet；
- radial basis；
- finite-element shape function；
- neural implicit field，但只能作为无晋级权表示层。

多区域归属由相场竞争产生：

\[ \chi_r(x,t) = \frac{\exp(\phi_r/\tau)} {\sum_k\exp(\phi_k/\tau)}. \]

或者在锐界面极限下：

\[ r(x,t)=\arg\max_k\phi_k(x,t). \]

因此：

- softmax 权重通常都大于零，只表示软成员重叠，不保证区域互斥；
- 空间覆盖和每个硬区域的非空性必须由独立验收证明；
- \(\phi_i=\phi_j\) 只能提供候选界面，方向、覆盖、两侧 trace 和守恒仍需独立验收；
- 区域数量、连通性、孔洞和分裂只能由场演化及拓扑审计确认为 phenotype。

若需要硬分区，拟议 profile 必须声明 `argmax` 的确定性 tie-break、覆盖域、非空、互斥、连通性和界面独立验收；不能把 softmax 的正权重当作不重叠或每域存在的证明。

一个 phase-field genome 可以写成：

```
{
  "field_id": "phi0",
  "field_role": "material_phase_logit",
  "basis_program": {
    "family": "adaptive_wavelet",
    "active_terms": [
      {"level": 1, "index": [0,0,0], "coefficient_gene": 0.42},
      {"level": 2, "index": [1,0,2], "coefficient_gene": -0.31}
    ]
  },
  "classification_role": "region_partition",
  "complexity_cost": 2
}
```

这里的 basis 是数值坐标系，不是装置组件。候选必须在 Fourier、wavelet 或网格加密后保持主要表型，才能证明结果不是某种 basis 的伪影。

## 3. 场源如何编码

不直接生成“第几号线圈”，而是生成连续电流、荷电、热、粒子和动量源。

### 磁场和电流

在连续域内、具有足够光滑性且边界/接口兼容时，

\[ \nabla\cdot B=0, \]

不直接搜索 \(B\)，而是搜索矢势：

\[ B=\nabla\times A_B. \]

为了构造稳态无散电流，可以搜索电流势：

\[ J_{\rm ext} = \nabla\times\left(\chi_c A_J\right). \]

其中 \(\chi_c\) 是允许导电的材料相场。这样：

\[ \nabla\cdot J_{\rm ext}=0 \]

连续表示可在声明条件下保证散度恒等式，但离散后仍需 compatible finite-element/finite-volume 复合、界面项和离散误差验收；不能省略这些物理和数值义务。

`curl(chi_c A_J)` 在相场梯度或锐界面处会产生额外分布/界面项，不能把 `div(curl(A))=0` 当作无条件的物理或离散保证。拟议 profile 必须声明光滑性、分布意义、显式界面电流、边界条件和离散 curl-div 相容性，并单独验收界面项与散度误差。

在非平凡拓扑或给定边界条件下，不能默认全局单值势或周期势的 curl 基覆盖所有可容许的无散场。UP2 的可执行检查必须计算循环通量/环流，并显式登记调和（上同调）自由度，或提供等价的 cut、多图册和过渡映射表示；缺少这些自由度时只能声明受限场空间。拓扑事件之后必须重建循环基、约束和守恒传递，并用一个非平凡域的负例证明“换一组局部 basis”不足以闭合该场空间。

```
PotentialFieldGene
├─ potential_id
├─ output_field_kind
├─ construction_operator
├─ support_phase_refs[]
├─ basis_terms[]
├─ gauge_condition
├─ amplitude_gene
├─ temporal_program
└─ source_budget_refs[]
```

例如：

```
{
  "potential_id": "aj0",
  "output_field_kind": "current_density",
  "construction_operator": "CURL_OF_PHASE_WEIGHTED_VECTOR_POTENTIAL",
  "support_phase_refs": ["phi_conductor"],
  "gauge_condition": "zero_mean_coulomb",
  "amplitude_gene": {
    "transform": "signed_log",
    "bounds": [-1e8, 1e8],
    "normalized_gene": 0.27
  }
}
```

后续求解器获得的是连续 \(J_{\rm ext}(x,t)\)。只有当这个场通过物理门后，realization 编译器才尝试把它离散成：

- 体电流分布；
- 表面电流势；
- 导线和线圈；
- 电极；
- 束流或其他实际源。

## 4. 其他源如何编码

粒子、热和动量源可统一表示：

\[ Q_a(x,t) = A_a\, g_a(\phi,x,t)\, \operatorname{softplus} \left( \sum_j c_{aj}\psi_j(x)T_j(t) \right). \]

`softplus` 用于必须非负的源；有正负方向的源使用 signed basis。

```
SourceFieldGene
├─ source_id
├─ account_kind
├─ target_state_ref
├─ support_predicate
├─ positivity_rule
├─ basis_program
├─ temporal_program
├─ total_budget
├─ unit_signature
└─ actuator_binding_status
```

总量通过积分约束归一：

\[ \int_\Omega Q_a\,dV \le Q_{a,\max}. \]

因此搜索不能通过增加更多 basis coefficient 凭空获得无限功率或粒子输入。

## 5. 边界基因如何编码

边界本身由相场零水平集产生：

\[ \Gamma_{ij} = \{x:\phi_i(x)=\phi_j(x)\}. \]

genome 编码的是界面上的物理算子：

\[ \mathcal B \left( z^-, z^+, n, \kappa, u \right)=0. \]

```
InterfaceOperatorGene
├─ interface_selector
├─ minus_phase_ref
├─ plus_phase_ref
├─ trace_input_refs[]
├─ operator_ast
├─ paired_conservation_accounts[]
├─ jump_conditions[]
├─ direction_rule
├─ validity_bounds
└─ failure_scope
```

例如：

```
normal particle flux continuity
tangential field jump from surface current
thermal contact resistance
sheath loss
radiation transmission/reflection
moving-interface force balance
```

这些仍然使用 typed operator AST，而不是字符串标签。

## 6. 动态几何如何编码

如果边界会运动，搜索的是相场演化律：

\[ \partial_t\phi + v_n|\nabla\phi| = D_\phi\nabla^2\phi - \frac{\partial V(\phi)}{\partial\phi}. \]

这只是拟议演化方程的示意；可执行合同还必须声明 mobility、势函数及其单位、守恒型/非守恒型形式、初值、边界通量、时间尺度和离散稳定性。拓扑事件需要对应的物理项、事件触发和守恒/熵审计，不能通过换 basis 或直接写入 topology flag 产生。

对应 genome：

```
GeometryEvolutionGene
├─ evolved_phase_ref
├─ normal_velocity_program
├─ curvature_term
├─ diffusion_or_regularization
├─ driving_state_refs[]
├─ event_triggers[]
└─ topology_change_permission
```

拓扑事件不直接写成“生成一个孔”或“分裂成两个区域”，而是由场演化产生，再由审计器检测：

- 连通分支数变化；
- Betti number 变化；
- 区域 birth/death；
- 接触、断裂或合并；
- 接口方向变化。

## 7. 哪些不能作为输入基因

下面这些应当是 phenotype，不应直接参与搜索：

- 磁轴位置；
- 闭合磁通面数量；
- 岛链数量；
- rotational transform；
- 分离面和 X-point；
- 场线逃逸时间；
- 区域体积；
- 曲率分布；
- genus/Betti number；
- 线圈数量；
- normal-field residual；
- equilibrium、stability、transport pass。

这些量必须由场求解、轨道追踪或拓扑分析计算。否则搜索器可以直接“声明自己有闭合磁面”。

## 8. Canonical genome

同一物理场可能有很多不同表示，必须消除表示冗余：

### 几何规范化

- 平移到质心；
- 主惯性轴定向；
- 统一长度尺度；
- phase label 规范排序；
- signed-distance reinitialization；
- 删除低于声明容差的 basis 项；
- 合并重复 basis 项。

### 场规范化

矢势有 gauge 等价：

\[ A\rightarrow A+\nabla\lambda. \]

因此可以：

- 固定 Coulomb gauge；
- 固定零均值；
- 或直接对物理 \(B\)、\(J\) 的采样/谱表示哈希，而不对原始 \(A\) 哈希。

### 分层哈希

```
spatial_support_hash
phase_partition_program_hash
source_program_hash
interface_program_hash
field_geometry_genome_hash
materialized_geometry_hash
field_solution_hash
emergent_topology_hash
realization_hash
mesh_and_evaluation_hash
```

其中 `field_geometry_genome_hash` 不包含网格分辨率；网格和 solver 设置进入 `evaluation_hash`。

## 9. 变异操作

场—几何 genome 使用结构化变异：

- 添加/删除一个局部 wavelet mode；
- 提升某个空间区域的 basis level；
- 分裂或合并 phase field；
- 改变相场之间的耦合；
- 添加一个无散电流势模态；
- 将静态源改为有界时变源；
- 添加界面动力学；
- 改变对称生成元；
- 添加一个新的 chart；
- 局部移动隐式边界；
- 将局域源转换为非局域响应源。

每次变异后必须重新执行：

- 单位检查；
- phase partition 完整性；
- 电荷连续性；
- \(\nabla\cdot B=0\)；
- 源功率和材料体积预算；
- 最小间距和曲率下界；
- 网格可解析性；
- 受影响的物理硬门。

## 12. 空间组合合同与三层实现义务（拟议）

G2 的输入输出分三层，不能把一层的声明当成下一层已经完成：

```text
抽象拓扑（region/interface/exterior/event）
        ↓ 必须有物化规则、方向和守恒账户
连续几何与场（charts、phase、metric、potential、boundary law）
        ↓ 必须有可解析性、质量和离散收敛义务
网格/积分/离散对象（cells、faces、DOF、quadrature、solver input）
```

|层|必须提供|通过条件|
|---|---|---|
|一般区域|region identity、连通/孔洞声明、材料/场归属和时间域|相场/隐式区域可判定，边界不重叠且覆盖合同闭合|
|边界/接口|定向两侧、法向、trace、jump/flux law、守恒账户|界面项成对，方向一致，边界条件与 G1/G3 端口完全绑定|
|空间拓扑|连通分支、周期、chart transition、拓扑事件模型|拓扑变化由合法连续演化或物理事件产生并可审计|
|外部域|真空/回路/壁/返回路径等域及其 provider|外部输入、边界回流和资源预算不以默认零替代|
|离散化|mesh generator、DOF mapping、quadrature、质量/误差估计|几何、场、网格、solver input 各有 hash，具备网格/基函数收敛检查|

磁重联、磁岛生成、分离面重构、区域 birth/death 之类拓扑变化，不能只通过更换 Fourier/wavelet 基或改一个边界系数宣称完成。拟议 `TopologyEventModelV2` 必须声明适用物理（例如电阻、非理想项、界面断裂或相场跃迁）、触发条件、守恒/熵影响、时间尺度和可观测量；没有相应物理模型时最多是 `unknown` 或 `deferred`。

G2 field coefficient 数量只衡量生成程序复杂度；网格 DOF 由 `DiscretizationProfileV2`（拟议）和具体 mesh 共同产生，包含节点、单元、面、quadrature 与 solver unknown。两者必须在 manifest 中分列，避免通过网格细化假造“新几何基因”或把 basis 维数当作装置能力。

## 13. 按统一路线的 G2 执行合同（拟议）

### UP0：基线合同

- 输入：现有 `FieldGeometryGenomeV4`、G2 5.3 typed field programs、SpatialRuntimeV4 的两区域实例、显式 geometry/mesh artifacts 及其历史 hash。
- 输出：`G2BaselineContractV1`（拟议），列出当前支持的 chart/phase/program、静态区域假设、网格 DOF 及未覆盖的外部域/拓扑。
- 步骤：冻结 V4/V1 字节和 profile；逐项审计 support/chart/metric/field program/root/parameter；分离抽象图、连续场、显式网格和 provider receipt。
- 正向测试：相同 candidate/scenario/grid 可重放同一 field plan/result/hash；field program 的唯一 ASTInput、root、parameter binding 与 operator manifest 完整。
- 反向测试：删除 chart transition、错配 root/parameter、改变 grid 仍沿用旧 result、声明闭合磁面但无求解 artifact 均拒绝或转 deferred。
- 退出门：旧证据保持原值；当前两区域 runtime 的范围和 credible 0 状态明确记录。
- 失败处理：只登记 capability gap，不把当前静态实例推广为一般 G2。

### UP1：三 Genome 合同和最小可执行组件

- 输入：UP0、拟议 G2 schema/profile、一个最小 region/interface/exterior typed graph 和一个可离散 field program。
- 输出：版本化 G2 admission/migration 规格、最小抽象拓扑到连续场再到网格的编译计划（拟议）。
- 步骤：增加 profile/hash 引用；实现一般区域/边界/接口的 typed declarations；复用现有 field program evaluator，仅扩展入口和 gap 报告，不宣称任意空间求解。
- 正向测试：两个区域、一个定向 interface、一个外部域和最小 chart 能物化为有确定性身份的 geometry/mesh plan；接口账户与 G1 occurrence 成对。
- 反向测试：区域重叠/缺失、接口方向反转、外部域未绑定、网格无法解析窄结构、把 region label 当 mesh proof 均 fail closed。
- 退出门：有明确的 support、geometry、mesh、provider 和 scenario hash；无物理 solver 时保持 `screen_only`/`deferred`。
- 失败处理：区分 geometry invalid、mesh unresolved、具体 provider `match_reason`、numerical fail 和未执行；分支终态使用 `deferred`/`terminal_deferred`，最终 authority 才能签发 `unsupported`。

### UP2：物理编译、空间离散和耦合层

- 输入：UP1 G1/G2 typed contracts、边界/接口 law、field/source program、材料和外部域能力签名。
- 输出：连续场求解输入、守恒转移/接口 flux assembly、可追溯 mesh/DOF mapping、收敛与不确定度收据（拟议）。
- 步骤：将 phase/field program 评价为连续场；物化区域、接口、外部域；生成 mesh 与 quadrature；把 G1 residual 的 spatial terms、G3 source basis 和 interface transfer 接入同一耦合残差。
- 正向测试：制造场/区域恢复、接口通量配对和全局守恒、网格加密/基函数变更下的收敛与误差界、外部域回路闭合。
- 反向测试：后处理拼接 reaction/radiation/actuator、没有 pressure/current topology closure、仅固定两区域实例、mesh 非收敛或外部域缺失均不能称为 coupled pass。
- 退出门：所有 spatial unknown/DOF、有界源、接口和 provider 都在同一输入/输出收据中；失败时保留残差和 solver exit。
- 失败处理：不把不收敛当作永久无解；按 `numerical_fail`、`physical_fail`、`unknown`、`deferred` 保存 failure frontier，并记录具体 match reason。

### UP3：合法组合自动执行

- 输入：通过 UP2 的 G1/G2/G3 prefixes、拓扑事件模型和完整 capability signature。
- 输出：合法组合的 geometry/mesh/solver manifests、可重放结果和缺口前沿（拟议）。
- 步骤：沿 canonical prefix DAG 扩展 region/interface/topology；每次拓扑或外部域改变均重建 candidate identity 和上游 receipts；按几何、物理、mesh 能力逐轴路由 provider。
- 正向测试：同一抽象拓扑的规范化表示 hash 一致；不同拓扑事件模型、外部域或 mesh profile 产生新 identity。
- 反向测试：按候选名猜 provider、将 empty capability 视为 wildcard、复用旧 mesh/result 证明新 topology、只改 basis 冒充重联均拒绝。
- 退出门：自动执行只证明物化链路和收据完整，不能授予闭合物理或工程 pass。
- 失败处理：不能物化的拓扑进入 `terminal_deferred`，低保真失败保留在 dormant/failure pool。

### UP4：逆向源硬件 realization 与供能/热结构反馈的 G2 责任

- 输入：通过 UP3 的连续目标场/源、外部域、接口应力与温度边界，以及 G3 source-basis/材料/网络合同。
- 输出：供 G3 逆向 realization 的目标场 trace、几何 clearance/曲率/热边界、反馈所需的场—热—结构耦合端口（拟议）。
- 步骤：导出带单位和误差界的连续 source target；计算场到实际网络的可实现约束；将温升、变形、材料属性变化反馈到 field/geometry；明确未闭合部分。
- 正向测试：离散 source 回代目标场的误差在声明区间，热/结构反馈迭代可复现且守恒；独立 mesh/basis 仍保留目标表型。
- 反向测试：任意目标场无源网络/功率约束仍判为可实现，或控制评分抵消 source mismatch，均拒绝。
- 退出门：只在 source capability、功率/热边界、几何可制造性和反馈收据齐全时进入工程候选。
- 失败处理：逆问题不可识别或能力不足记录可识别组合、误差适用域和具体 match reason，置为 `unknown`/`terminal_deferred`，不强行生成线圈/导线；最终 authority 才能依据证据分类 `unsupported`。

### UP5：条件 e-graph 与扩大演化搜索

- 输入：可重放 G2 graph/field/topology artifacts、条件 rewrite/checker、mesh-independent canonical identity。
- 输出：拓扑和场程序的 lineage、rewrite trace、分层 mesh/basis evaluation frontier（拟议）。
- 步骤：仅进行保类型、保区域/接口/守恒和带条件的重写；交替拓扑编辑、连续场优化和自适应离散；保存 abstract/geometry/mesh 三层 hash。
- 正向测试：合法重写保持接口方向、区域覆盖、外部域绑定和网格可解析性；不同 basis 对同一表型的比较有误差和收敛证据。
- 反向测试：rewrite 直接制造新 Betti 数、删除外部域、把网格拟合当 topology proof、surrogate 排名当物理证据均拒绝。
- 退出门：搜索只扩大声明 profile 的空间；没有物理模型的拓扑事件仍不晋级。
- 失败处理：checker 不确定为 `unknown`，资源/网格不足为 `deferred`，不得签发伪 no-solution certificate。

### UP6：整装 R01–R10 的 G2 责任

- 输入：最终三 Genome、连续场/几何/mesh/solver artifacts、独立 physics provider、VVUQ 和 replay 环境。
- 输出：G2 独立验收包，包含抽象拓扑→几何→网格的全链路 receipts。
- 步骤：复核区域/接口/外部域、拓扑事件物理、守恒转移、网格/基函数收敛、源硬件回代与不确定度；将 phenotype 与 G1/G3 的结构语义分开记账。
- 正向测试：至少一个候选通过适用的几何、物理、工程和独立验证门，并具备 candidate/provider/scenario/mesh/uncertainty/independence 绑定。
- 反向测试：只有固定两区域 screen、单网格、显式闭合曲面声明或文档构造器检查不得满足 R01–R10。
- 退出门：R01–R10 每一项都必须有逐项关账记录；声称某项不适用也必须由该项显式义务与 proof 关闭，不能忽略整个 R 项。只有全部关账才可更新 parent goal，否则 credible count 保持未闭合/0。
- 失败处理：按 `scientific fail`、`program exception`、`human interruption`、`not_executed`、`unknown` 和 `deferred` 分开记录并保留 match reason；`unsupported` 只能由最终 authority 依据证据签发。
