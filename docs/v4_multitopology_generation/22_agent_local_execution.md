# 智能体自主研发执行合同

生效：2026-09-17，依据用户明确要求“智能体自身就是负责人，不要有除了智能体之外的外部依赖和外部人为”及“执行修改”。默认配置为 [execution_policy.json](execution_policy.json) 的 `agent_local`。本章取代旧文件中将外部认证设为本地研发前置条件的规定；不改变 R01–R10 的科学与工程目标。

## 1. 谁负责

| 责任 | 执行者 | 实际产物 |
|---|---|---|
| 架构、任务依赖、范围裁决、最终项目内验收 | Sol 智能体 | 工作单、必要的版本化架构决策、逐项验收结论 |
| 源码、Genome、G2 映射、环境和运行记录 | 实现 Luna 智能体 | 实际文件、来源及哈希、可执行命令、输出和失败原因 |
| 重算与复放、反例、结果复核 | 不同的 Luna 智能体 | 对实际输入和产物的复核记录 |

这是项目内软件职责，不要求自然人身份、机构授权或证书。不同智能体复核属于项目内交叉检查，不等同于外部机构认证。物理独立验证仍要求不同算法、基准、分辨率或留出数据等实质独立依据，不能只换一个智能体签名。

## 2. 删除哪些主线前置条件

外部 CA/证书链、证明人签名、OCSP/CRL、TSA、接收端点及签名 ACK、外部防重放服务、发布方签发、EHP-01～04 齐套，以及外部权威 G2/四轴材料，均不再阻塞研发、候选身份生成、数值执行、项目内验收或搜索。无需给这些角色找人，也不新建本地 CA 来替代原来的复杂流程。

旧 R2/R3/R4 外部认证模块及历史收据保留为显式选用的兼容功能；不从正常主线调用。`26/26 typed_absent` 仍如实表示当时缺少外部认证材料，不再代表 UP1 技术任务必须停止。不能批量改写旧记录为 present，或把本地记录命名为 `externally_verified`。

## 3. 本地材料和检查

- 智能体直接创建版本化候选、G1/G2/G3 声明、parent/mission/scenario 绑定；标识只表示对象身份。修改后重算受影响的 hash 与谱系，旧结果不会自动转移。
- 源码记录以实际执行文件为准，记录 HEAD 与相关 dirty 内容；区分 Git canonical blob 与工作树原始字节。hash 证明内容一致，不证明物理正确。
- schema、canonicalization、applicability、evidence-receipt 四轴使用实际版本和字节，逐项验证适用性和一致性；可由智能体维护，不需要外部签发。
- G2 映射由实现智能体生成，复核智能体验证域、方向、量纲、边界、拓扑及守恒。只有声明为可逆的映射要求往返恒等；投影、网格传递和拓扑变化按其损失与守恒合同验证，不能一律要求双射。
- 环境使用实际解释器、模块、版本、锁文件和所选求解器所需依赖；缺少未选用的求解器不能阻塞当前任务。继续复用 Julia/Python 和成熟数值库；运行不依赖在线认证服务或外部人员放行。
- 输入缺失、源码冲突、单位错误、缺闭合、不支持的拓扑、数值失败及物理失败仍明确报错。解析解和 manufactured 输入可用于正常数值验证，但不能被报告为实验或整装证据。

## 4. UP1 到后续执行的具体转换

T0 保留完整声明、内容哈希和同候选绑定；recheck 改为本地来源与声明一致性复核；T1/T2 完成实际 package/edit 实现与反例。不再要求把 source-stage present 升为外部 trusted source 才能开始这些实现。AD-33/34 的“最多 typed-absent scaffold”属于旧实现状态，不再是未来开发上限。

旧 Julia authority API 中的 `trusted_receipt` 不能仅换个字符串便充当新验证。后续实现使用明确的本地记录/版本化适配器，验证实际 bytes、candidate、layer、declaration 和 source receipt 的绑定，再连接新 package；旧外部验证接口保持原语义。本次修改不声称这些尚待完成的 Julia 集成已经实现。

UP1 的完成条件仍是 Genome 合同、合法与非法构造、迁移、标签擦除及最小组件数值验证。UP2–UP6 的编译、组合、逆实现、工程反馈、搜索和终局验证照常执行。Sol 可修改不合理的 DAG 依赖、拆并任务；需同步机器清单和工作单并检查无环，节点数不冻结。不得把未做的技术任务直接标为 accepted。

## 5. 正常开发入口

在仓库根执行：

```powershell
python -B tools/agent_local_execution.py
python -B docs/v4_multitopology_generation/validate_plan.py
```

前者读取当前策略和任务清单，列出技术依赖已满足的任务，不读取外部认证结果。后者检查路线、工作单与策略一致。需要留存一次实际命令时使用：

```text
python -B tools/agent_local_execution.py --task TASK_ID --input RELATIVE_SOURCE --input RELATIVE_TEST --output NEW_RUN_DIRECTORY --run EXECUTABLE ARGUMENTS
```

替换为工作单的真实任务、输入文件和命令；所有相关执行输入均应列入 `--input`。输出目录必须新建；记录输入及日志哈希、命令、退出码，并拒绝执行前后输入变化。超时默认 300 秒，可显式设置 `--timeout`；命令可能生成的子进程仍按项目重计算串行规则管理。本工具是开发调度与记录器，不是 Genome 语义验证器或物理验收器；退出 0 不关闭任何任务。现有直接 Julia/Python 命令也可使用同一合同，不强制再包一层启动器。

## 6. 归档和优先级

冲突时先遵循最新用户指令和本章，再读当前工作单；历史验收仅说明当时输入、行为和结论。旧外部门不再叠加为隐藏前置条件。实现者不需要阅读全部 AD 才能开始，工作单必须列出当前输入、文件范围、技术步骤、验证命令和退出条件。

本次修改的前态、检查和范围见 [修改档案](../implementation/AGENT-LOCAL-EXECUTION-20260917/README.md)。既有数值切片只按自己的证据验收，不因本次政策改变而自动关闭 UP 阶段、增加 L4 数量或补出实验结果。
