# G1 机制基因组升级规划（拟议）

> 统一声明：本文新增的 V2/V5、profile、migration receipt、compiler 和 gate 均为拟议；UP0–UP2 的合同、输入输出、阈值和身份规则必须先冻结，再进入 UP3–UP6。四个版本轴分别是 payload schema version、canonicalization/hash profile version、grammar/capability applicability profile version、execution/evidence receipt version；它们不能互相替代。V1/V4 历史哈希和证据保持不变。

可以把机制基因组严格定义成一个“带类型、单位和守恒约束的可变长度算子程序”：

\[ \mathcal G=(S,I,O,E,\Theta,Y,U) \]

其中：

- \(S\)：状态基因；
- \(I\)：守恒/不变量基因；
- \(O\)：算子程序；
- \(E\)：算子依赖与耦合边；
- \(\Theta\)：连续参数；
- \(Y\)：可观测量；
- \(U\)：尚未闭合的假说算子。

它不是一条普通浮点向量；canonical genome 是一张 typed operator graph。需要给遗传算法使用时，再打包成整数 token、邻接表和连续参数向量。

## 1. 状态基因如何编码

每个状态变量使用固定记录：

```
StateGene
├─ state_id
├─ value_kind
├─ tensor_rank
├─ spatial_dimension
├─ time_kind
├─ unit_signature[7]
├─ lower_bound
├─ upper_bound
├─ parity_flags
├─ gauge_or_constraint_refs
└─ epistemic_state
```

例如：

```
{
  "state_id": "s0",
  "value_kind": "scalar_field",
  "tensor_rank": 0,
  "spatial_dimension": 3,
  "time_kind": "differential",
  "unit_signature": [0, -3, 0, 0, 0, 0, 0],
  "bounds": [1e12, 1e24],
  "parity_flags": ["even_under_time_reversal"]
}
```

`unit_signature` 使用七个 SI 基本单位的指数：

\[ [\mathrm{kg},\mathrm{m},\mathrm{s},\mathrm{A}, \mathrm{K},\mathrm{mol},\mathrm{cd}] \]

例如：

- 数密度 \(\mathrm{m}^{-3}\)：`[0,-3,0,0,0,0,0]`
- 能量密度 \(\mathrm{J/m^3}\)：`[1,-1,-2,0,0,0,0]`
- 磁场 T：`[1,0,-2,-1,0,0,0]`

单位不是描述性元数据，而是编译器执行算子组合合法性检查的类型。

## 2. 守恒基因如何编码

守恒基因不是“mass=true”这种标签，而是状态与源汇之间的稀疏账户：

```
InvariantGene
├─ invariant_id
├─ account_kind
├─ scope (typed)
├─ state_coefficients[]
├─ owned_ledger_occurrence_refs[]
├─ tolerance_log10
└─ entropy_direction
```

例如粒子账户：

```
{
  "invariant_id": "i0",
  "ledger_identity": {
    "account_kind_ref": {"id": "particle_number", "version": "v1"},
    "ontology_hash": {"value": "<64-hex-digest>"},
    "unit": {"exponents": [0, 0, 0, 0, 0, 0, 0]}
  },
  "scope": {"kind": "global"},
  "state_coefficients": [
    {"state_ref": "s0", "coefficient": [1, 1]}
  ],
  "owned_ledger_occurrence_refs": [
    {"operator_site_ref": "source0", "port_side": "output", "port_index": 1,
     "direction": "plus", "occurrence_kind": "occurrence_source_effect",
     "ledger_identity": {
       "account_kind_ref": {"id": "particle_number", "version": "v1"},
       "ontology_hash": {"value": "<64-hex-digest>"},
       "unit": {"exponents": [0, 0, 0, 0, 0, 0, 0]}
     }}
  ],
  "tolerance_log10": -8
}
```

`scope` 是封闭的 typed value，而不是可自由解释的字符串：`global` 不带目标；
`domain` 携带非空、去重并规范排序的 `state_refs`，只表示 G1 的状态分区；
`interface` 携带一个精确的 operator-site ref，并要求该 interface edge 声明同一完整守恒账户。
scope 的引用必须在当前 typed operator hypergraph 中精确闭合，失败时保留
`legacy_gene_semantics_unrepresentable`，不猜测旧版本的 ref 或 domain 语义。这里的 domain
不是 G2 场区域，也不宣称已经完成区域 ownership；G2 的几何/场边界仍由其自身 Genome 声明和验证。

每个 graph account effect 通过 MIMO 的精确 `program_position` 绑定到 endpoint node，
再规范化为 occurrence。公共 `ConservationLedgerOccurrenceRefV1` 只含
`operator_site_ref`、`port_side`、`port_index`、`direction`、`occurrence_kind` 和完整
`ledger_identity`；系数只存在于内部 normalized occurrence，不参与 occurrence owner key。
`port_index` 必须与该 edge 的 MIMO binding `program_position` 精确匹配，并由该 binding
解析到 endpoint node；不能仅按端口序号猜测图节点。
occurrence kind 由 typed edge role 派生：`occurrence_source_effect`、
`occurrence_sink_effect`、`occurrence_boundary_effect`、`occurrence_internal_effect`，以及
interface 的 `occurrence_interface_minus/plus`。系数用有理数 `[numerator, denominator]`，避免浮点误差改变 genome hash。

payload admission 要求每个 invariant 的声明 occurrence 集与其 scope/ledger 在图中推导出的
期望集双向相等，所有 invariant 的 ledger 集等于图中所有 occurrence 的 ledger 集，且每个
`(完整 ledger identity, 精确 typed scope)` owner 唯一；不同或重叠 scope 可以同时存在。

后续物理编译阶段仍需验证：

\[ \frac{d}{dt}I_k = \text{declared sources} -\text{declared sinks} -\text{boundary fluxes}. \]

该 structural ownership slice 只建立 occurrence 的 typed identity、scope 闭包和 owner
关系；它不实现、也不证明上述方程的数值守恒或 C0 物理拒绝。任何“内部算子凭空产生账户”
的判定必须由后续物理/编译阶段单独完成，不能从本 slice 的 ownership 结果推断。

## 3. 算子基因如何编码

每个物理表达式编码成 typed AST 节点。

```
OperatorGene
├─ opcode
├─ input_refs[]
├─ output_signature
├─ parameter_refs[]
├─ locality
├─ derivative_order
├─ causal_direction
├─ conservation_effect[]
├─ validity_bounds
└─ assembly_role
```

第一版可以定义约 30–50 个基础 opcode：

```
代数：
ADD, NEG, MUL, DIV, POW_RATIONAL, CONTRACT

时空：
DT, GRAD, DIV_OP, CURL, LAPLACE, MATERIAL_DERIVATIVE

通量：
ADVECT, DIFFUSE, ANISOTROPIC_FLUX

约束：
PROJECT_DIVERGENCE_FREE, ALGEBRAIC_CONSTRAINT

非局域：
INTEGRAL_KERNEL, CONVOLUTION, DELAY

动力学：
POISSON_BRACKET, RELAXATION, STOCHASTIC_DRIVE

事件：
THRESHOLD_SWITCH, DOMAIN_BIRTH, DOMAIN_DEATH

未知：
TYPED_OPERATOR_HOLE
```

一个守恒方程可以编码为：

```
o0 = DT(s0)
o1 = GRAD(s0)
o2 = APPLY_TENSOR(p0, o1)  # 拟议 GrammarProfile 伪代码；当前默认 registry 不可执行
o3 = ADVECT(s0, s1)
o4 = ADD(o3, NEG(o2))
o5 = DIV_OP(o4)
r0 = ADD(ADD(o0, o5), NEG(source0))  # ADD 当前按二元 typed operator 组合
```

对应：

\[ \partial_t s_0+ \nabla\cdot \left(s_0s_1-\mathbf D\nabla s_0\right) -S_0=0. \]

算子节点同时保存输入和输出的单位、张量秩及空间维度。比如 `GRAD` 自动完成：

\[ \text{scalar}\,[u] \rightarrow \text{vector}\,[u\,\mathrm m^{-1}]. \]

因此不需要枚举所有可能公式；使用类型正确的程序组合生成公式。

这里的 `GRAD`、`DIV_OP`、`ADVECT` 等并非无条件的字符串变换：拟议 profile 必须同时绑定 chart、metric、orientation、时间语义和单位；导数/通量支持不足时只能产生 obligation 或 `deferred`。`MUL`、`DIV`、`ADD` 的结合与常量折叠也必须经过 typed canonicalization，不能依赖裸浮点或可变参数元组。

## 4. governing、additive 和 constraint 基因

每个 residual block 必须声明角色：

```
{
  "residual_id": "r0",
  "row_state_ref": "s0",
  "root_operator_ref": "o5",
  "assembly_role": "governing"
}
```

规则是：

- 每个 differential/algebraic 状态恰好有一个 `governing` residual；
- 可以有任意数量的 `additive` residual；
- algebraic 状态必须对应 `constraint`；
- 接口通量必须成对出现、方向相反；
- mass matrix 和 Jacobian sparsity 由程序图推导。

这份示例只能作为拟议 GrammarProfile 的 typed 伪代码：`APPLY_TENSOR` 不在当前默认 registry，`MUL`/`DIV`/`ADD` 必须按当前或新增 profile 的精确输入输出类型规范化。历史 v68/RuntimeV4 只能作为其有限已支持子集的边界参考，不能把示例直接宣称为通用编译器能力。[v68/RuntimeV4 编译约束](D:\\006-Programing\\LMC\\FusionConceptAI\\src\\RuntimeV4\\ThreeDGoverningResidualJacobianV4.jl)

## 5. 连续参数如何进入 genome

所有物理参数保存三个东西：

```
ParameterGene
├─ transform
├─ physical_lower
├─ physical_upper
└─ normalized_gene
```

搜索变量统一为：

\[ g_i\in[-1,1]. \]

正数跨数量级参数使用对数映射：

\[ \theta_i= \exp\left[ \log\theta_{\min} +\frac{g_i+1}{2} \left(\log\theta_{\max}-\log\theta_{\min}\right) \right]. \]

普通有限参数使用线性映射。需要正负跨尺度时使用 signed-log。

这样：

- genome 中没有 `Inf`；
- 参数边界可哈希；
- 不同单位和数量级可以使用统一变异尺度；
- 参数变化必须改变包含该参数实例的 `candidate_subject_hash`/bundle/input identity；若只需结构描述，应使用现有 `mechanism_structure_hash`，不能让核心 `decorated_mechanism_hash`（`mechanism_hash`）忽略实际机制参数。

## 6. 对称性如何编码

不只保存 `"axisymmetric"` 名称，而保存作用生成元：

```
SymmetryGene
├─ coordinate_generator_matrix
├─ state_action_matrices[]
├─ group_order
├─ invariant_or_equivariant
└─ tolerance
```

例如离散旋转只需要：

- 坐标变换矩阵 \(R\)；
- 阶数 \(n\)；
- 约束 \(R^n=I\)；
- 各状态在 \(R\) 下如何变换。

这样可以生成螺旋、反射、复合离散对称性，而不是从装置类别表里选择。

## 7. 未知机制如何编码

允许 `TYPED_OPERATOR_HOLE`，但它不是任意空白：

```
{
  "opcode": "TYPED_OPERATOR_HOLE",
  "inputs": ["s0", "s1"],
  "output_signature": {
    "kind": "vector_field",
    "unit_signature": [0, -2, -1, 0, 0, 0, 0]
  },
  "allowed_conservation_effects": ["redistribute_only"],
  "forbidden_conservation_effects": ["net_energy_creation"],
  "maximum_ast_nodes": 12,
  "maximum_derivative_order": 2,
  "maximum_memory_length": 1,
  "null_model_ref": "u0_null",
  "alternative_model_refs": ["u0_alt1", "u0_alt2"],
  "observable_refs": ["y0", "y1"]
}
```

搜索器可以用符号回归、枚举、稀疏辨识或 learned operator 填这个 hole，但在候选绑定验证完成前只能保持 `unknown`。

现有 `PartialOperatorV2` 已经具备输入输出、守恒影响、复杂度预算、null/alternative model 和可辨识条件，可直接扩展。[现有 schema](D:\\006-Programing\\LMC\\outputs\\fusion_concept_ai\\schemas\\partial_operator_v2.schema.json)

## 8. 可观测量也必须是基因

原创机制如果没有独特可观测预测，无法与已有机制区分。

```
ObservableGene
├─ expression_root
├─ intervention_ref
├─ sampling_operator
├─ expected_effect_interval
├─ noise_model
├─ minimum_effect_size
└─ competing_prediction_refs
```

例如：

\[ y_0= \int_{\Omega} w(x)\,s_0(x,t)\,dx \]

并声明在某个干预 \(u(t)\) 下：

\[ \Delta y_0\in[0.15,0.30], \qquad \sigma_{\rm noise}+\sigma_{\rm numerical}<0.03. \]

如果候选提出的新算子与 null model 的预测差异低于噪声和数值误差，直接判为 `unidentifiable`，不进入正式机制档案。

## 9. Canonical genome 与多个哈希

同一个公式可能有不同写法，因此必须规范化：

- 状态 α-renaming；
- commutative operands 排序；
- 单位归一；
- 常数约分；
- 消除 `ADD(x,0)`、`MUL(x,1)`；
- 公共子表达式合并；
- operator DAG 图同构规范化；
- 参数转成无量纲 \(\Pi\) 群；
- realization 信息从机制身份中删除。

然后生成分层身份：

```
ontology_hash
operator_structure_hash
mechanism_structure_hash
decorated_mechanism_hash
candidate_subject_hash
realization_hash
behavioral_signature_hash (拟议描述子)
```

现有 `mechanism_structure_hash` 可只描述状态、守恒、拓扑和 operator DAG 的结构；核心 `decorated_mechanism_hash`（`mechanism_hash`）还必须包含实际规范化参数、对称性和可观测预测。它不应包含 realization 专属信息，例如：

按当前源码分层，`mechanism_hash(m)` 是 `decorated_mechanism_hash`，`mechanism_subject_hash` 是 `candidate_subject_hash`；`genome_bundle_hash` 还要把 `MechanismGenome` 的 canonical `semantic_view` 纳入 bundle。因而参数实例必须影响 `decorated_mechanism_hash`、`candidate_subject_hash` 及其 bundle/input 身份；纯结构比较使用现有 `mechanism_structure_hash` 等描述子，不能拿结构哈希替代实例证据。

- 装置名称；
- 线圈编号；
- 材料供应商；
- 几何 realization。

这样相同机制的不同装置实现会归到一个机制等价类。

## 10. 遗传操作如何定义

不做普通 bit flip，而做保持类型的事务式变异：

- `add_state_with_governing_residual`
- `remove_unobserved_state`（拟议，只有等价约束/可辨识性/保护故障保留证书通过才允许）
- `split_state_by_timescale`
- `replace_operator_subtree`
- `local_to_nonlocal_flux`
- `add_feedback_path`
- `add_or_break_symmetry`
- `introduce_event_rule`
- `add_typed_operator_hole`
- `merge_equivalent_states`（拟议，必须输出等价映射、约束保持和故障/保护影响证书）

交叉只允许在以下条件同时满足时交换子图：

- 输入输出单位相同；
- 张量秩相同；
- 守恒作用兼容；
- 因果方向兼容；
- residual ownership 不被破坏。

否则 crossover 无效，不使用自动“修好”来掩盖物理矛盾。

## 建议的 v1 有限边界

第一版不要立即做成无限递归语法，建议：

|基因对象|v1 范围|
|---|---|
|状态场|2–8|
|operator AST 节点|4–32|
|governing residual|等于状态数|
|additive residual|0–16|
|不变量/账户|1–6|
|连续参数|0–16|
|可观测量|1–8|
|typed operator hole|0–1|
|AST 最大深度|6|
|最高微分阶|2|
|非局域/记忆算子|各不超过 1|
|事件规则|0–2|

这已经不是现有组件的排列组合，而是数十亿到天文规模的合法物理程序空间。实际搜索不穷举，用 program synthesis、QD、Pareto 和 falsification-guided mutation 探索。

最核心的量化原则是：

> **基因保存“产生物理行为的最小程序”；区域、场线拓扑、组件和装置外形由求解及逆向 realization 产生。**

## 11. 升级边界：当前实现、拟议扩展与版本迁移

本节是后续升级规划，带有“拟议”前缀的类型、profile、接口和文件名均不是当前构造器的声明。

当前源码已经实际提供 `MechanismGenomePayloadV1`、`TypedASTProgramV1`、`AtomicMIMOHyperedgeV1`、精确守恒 occurrence ownership、observable/hole 引用闭合，以及历史 v68 的 residual block 检查。`MechanismGenomePayloadV1` 的 `2:8` 状态上限和总 AST 节点上限 32 是该 payload 的 admission bound，不是物理宇宙或未来 Grammar 的上限；字段数量也不能当作离散网格自由度。当前 operator registry 仍是封闭清单，v68 compiler 也还没有泛化为任意 G1 程序的物理编译器。因此现有 typed AST/hypergraph 是可复用的核，不等于 UP1 之后的开放生成能力已经存在。

源码依据：`src/Genomes/MechanismGenomePayload.jl` 的 admission/ownership/上限检查、`src/IR/OperatorHypergraph.jl` 的 MIMO edge 与 role 定义，以及 `src/RuntimeV4/ThreeDGoverningResidualJacobianV4.jl`、`FieldResidualPipeline.jl` 的 residual/Jacobian 与 field coupling 审计。

拟议版本如下：

```text
G1SchemaProfileV2 (拟议)
├─ schema_uri, schema_version, schema_hash
├─ canonicalization_profile, canonicalization_hash
├─ grammar_profile_ref
├─ state_count_bound, ast_node_bound, parameter_bound
├─ field_count_semantics        # 机制字段/程序对象数量
├─ discretization_semantics_ref # 网格 DOF 由 G2 离散化合同给出
└─ migration_policy
```

`MechanismGenomePayloadV2`（拟议）必须携带上述 schema/profile 引用，并将每个 operator manifest 的状态性、闭合条件、适用域、守恒/源汇效应、导数支持和复杂度预算纳入 canonical payload。V1 的 schema hash、canonicalization hash、历史 candidate hash 和历史证据保持原值；V2 只产生新的版本化身份，禁止把 V2 字节覆盖到 V1 哈希上。

拟议的 `G1MigrationReceiptV2` 只允许逐字段、逐引用的可审计迁移：记录 source URI/version/schema hash/canonicalization hash、目标 profile、保留字段哈希、丢失或无法表示的语义、迁移工具版本和结果状态。无法证明等价的旧 edge、旧 scope 或未闭合 operator 必须记录具体 `match_reason` 并进入 `unknown`/`terminal_deferred`，不能以默认节点、默认域或猜测的守恒账户补齐；最终 authority 才能依据证据分类 `unsupported`。

## 12. 可组合算子与可扩展 GrammarProfile（拟议）

每一个可生成 operator 必须具有以下可组合合同：

|合同项|必须声明|编译时义务|
|---|---|---|
|类型闭合|输入/输出 `PhysicalType`、单位、张量秩、时空维度|所有输入端口和输出端口精确匹配；禁止隐式单位转换|
|状态语义|纯/有状态、记忆长度、内部状态 owner|有状态算子必须声明初始化、更新和 reset 规则|
|适用域|状态变量范围、无量纲参数域、几何/时间域|候选超域输出 `not_applicable` 或 `terminal_deferred`，不能外推成物理成立|
|效应|账户增减、重分配、边界通量、熵方向、源预算|与 G1 occurrence ownership 双向闭合；数值守恒留给 UP2 物理编译验证|
|导数支持|最大导数贡献、可用 Jacobian/Hessian、差分 fallback 上限|残差编译必须知道导数策略；无导数支持时降低证据级别或停在 deferred|
|闭合|需要的 constitutive law、参数、边界/接口端口、外部 provider|未闭合输入不得由 compiler 猜测；记录 match reason 并进入 `unknown`/`terminal_deferred`|
|资源|复杂度、内存、非局域跨度、事件预算|受 GrammarProfile 有界预算约束并记录实际消耗|

拟议 `GrammarProfileV2` 应采用“有界、可扩展轴”而不是把 30–50 个 opcode 写死在 Genome：

```text
GrammarProfileV2 (拟议)
├─ allowed_operator_refs[(id, version, manifest_hash)]
├─ type_rules, effect_ontology, closure_rules
├─ derivative_capabilities, locality/memory/event budgets
├─ admissible_domains[]
├─ max_states/max_program_nodes/max_parameters
├─ extension_refs[]              # 新 operator 必须独立版本和 manifest hash
└─ profile_hash
```

“可扩展”只表示在声明的适用域和预算内可以增加新 operator manifest；它不表示一次覆盖任意等离子体、任意拓扑或任意尺度。operator registry 扩展必须使用 candidate-owned/additive profile，不能静默修改旧 registry 或旧哈希。`TYPED_OPERATOR_HOLE` 仍只能保留在可辨识合同和 null/alternative model 之后，直到实现和观测绑定完成都只能是 `unknown`。

G1 的字段数量、AST 节点数和参数基因数必须与 G2 的网格 DOF、G3 的网络节点数分开记录。一个 field coefficient 的增加只改变生成程序；网格细化产生的 DOF 属于 G2 evaluation/discretization identity，不得伪装成机制复杂度或自由能量来源。

## 13. 按统一路线的 G1 执行合同（拟议）

以下每一项都是规划门；完成文档、接口测试或本地构造器检查本身不产生物理证据。

### UP0：基线合同

- 输入：现有 V1 payload、typed AST/hypergraph、operator registry、V1 canonical bytes、历史证据索引。
- 输出：`G1BaselineContractV1`（拟议）和不可变 hash/证据清单，明确 V1 bounds 与物理宇宙边界的区别。
- 步骤：读取并冻结旧 schema/profile/hash；列出每个状态、账户 occurrence、root、参数、observable、hole 的 owner；标出历史 v68 可作为参考的 structural slice 与未覆盖的 physical closure。
- 正向测试：同一 V1 payload 重放得到同一 canonical bytes；所有 governing/constraint、参数消费和 occurrence closure 通过。
- 反向测试：改动一个 schema/profile/hash、删除一个 occurrence、混入 legacy edge、越过 V1 bound，均被拒绝或标为明确迁移缺口。
- 退出门：基线和历史哈希可重放，旧 candidate 不被重写，credible count 仍按现行账本为 0。
- 失败处理：只生成审计缺口；不扩张 V1 构造器、不修改旧证据。

### UP1：三 Genome 合同和最小可执行组件

- 输入：UP0 基线、拟议 `G1SchemaProfileV2`/`GrammarProfileV2`、一组最小 typed operator manifest。
- 输出：版本化 G1 profile、V2 admission/migration 规格、一个 candidate-bound 的最小 AST/hypergraph 编译组件（拟议）。
- 步骤：实现 profile 引用和 manifest hash 校验；先支持类型/单位/状态/导数/效应审计，再以历史 v68 residual block 作为有限适配边界；不宣称开放搜索或物理闭合。
- 正向测试：闭合的 MIMO 程序、一个 governing row、一个 additive contributor、一个 algebraic constraint、双向账户 occurrence 和可观测 root 均能产生确定性编译计划。
- 反向测试：单位不匹配、重复 governing、缺参数消费、错误 program position、超适用域、无导数声明和无限预算都必须 fail closed；旧 V1 bytes 迁移后只产生新 V2 identity。
- 退出门：每个输出带 candidate/G1/profile/hash 绑定、输入输出和 gap；没有物理 provider 时只能 `screen_only`/`deferred`。
- 失败处理：区分 `program_exception`、`unknown`、`numerical_fail` 与 `terminal_deferred`，记录具体 match reason，不得用“编译成功”覆盖；`unsupported` 只能由最终 authority 依据证据签发。

### UP2：物理编译、空间离散与耦合层的 G1 责任

- 输入：通过 UP1 的 G1 程序、G2 区域/边界/网格合同、守恒账户和材料/源 provider 能力签名。
- 输出：统一 residual/flux/source assembly 计划、导数能力表、G1→G2 变量和端口绑定收据（拟议）。
- 步骤：将 governing/additive/constraint 组合成共享残差；验证状态覆盖、单位、区域/维度/时间、Jacobian slot、通量对和依赖；把网格 DOF 作为 evaluation input，不混入 G1 hash。
- 正向测试：制造解可恢复、守恒/接口配对成立、网格加密和不同合法离散实现保持候选语义；有限差分与声明导数在容差内一致。
- 反向测试：后求解追加 reaction/radiation/actuator、未配对界面通量、无 external closure、G1 适用域外场景均不得被称为 coupled pass。
- 退出门：共享残差真正包含全部声明贡献，具备 provider、scenario、grid、uncertainty 和 candidate hash；否则记录 match reason 并为 `unknown`/`deferred`。
- 失败处理：保留完整 residual、输入、迭代和退出码；不删除失败子树，不把低保真不收敛当作不可能证明。

### UP3：合法组合自动执行的 G1 责任

- 输入：通过 UP2 的 G1/G2/G3 candidate prefix 和 capability signature。
- 输出：可重放的合法组合清单、编译收据、失败前沿和候选 identity（拟议）。
- 步骤：用 canonical prefix DAG 组合 grammar/profile；每次改变 G1 声明都重建 candidate identity 并重新验证上游 receipt；只沿完整 capability axis 路由 provider。
- 正向测试：同一 prefix 顺序无关但 canonical identity 一致；不同 operator structure 或 profile hash 必须产生新 identity。
- 反向测试：按 family/name/候选编号猜 provider、空 capability 轴当 wildcard、复用外来 receipt 均拒绝。
- 退出门：自动执行仅证明组合和执行收据完整，不授予物理或工程 pass。
- 失败处理：低保真失败进入 failure frontier/dormant pool；缺 provider 或不适用进入 `terminal_deferred`。

### UP4：逆向源硬件 realization 与供能热结构反馈的 G1 责任

- 输入：UP3 的 G1 residual/observable contract、G2 连续目标场和 G3 source/资源/材料/控制候选。
- 输出：供逆向 realization 使用的方程、状态、守恒、源汇、导数和适用域约束收据（拟议）。
- 步骤：重新绑定 source/actuator 到 G1 的 typed state 和 ledger；把资源、热结构反馈需要的状态声明为明确 residual contributor；检查目标场不能绕过方程和守恒直接写入。
- 正向测试：source 回代残差、功率/热/结构反馈项、观测 root 和 Jacobian support 均能在同一 candidate-bound assembly 中追踪。
- 反向测试：把目标场当作无残差状态、添加无 owner 的源汇、由控制分数抵消守恒/闭合错误均拒绝。
- 退出门：G1 约束已被 G2/G3 消费且有 provider/uncertainty 绑定；这只开放 UP4 的 realization 输入，不授予物理或工程通过。
- 失败处理：缺少 constitutive/source closure 记录 match reason 并为 `deferred`/`terminal_deferred`；数值或物理失败继续保留原始 residual、退出码和 candidate identity，最终 authority 才能依据证据分类 `unsupported`。

### UP5：条件 e-graph 与扩大演化搜索的 G1 责任

- 输入：已有 candidate archive、profile 版本、条件 rewrite 和可 replay 的 checker。
- 输出：可审计 rewrite trace、QD/MCTS lineage、按预算扩展的 G1 搜索前沿（拟议）。
- 步骤：只应用带条件和 checker hash 的类型保持 rewrite；交替结构编辑与连续参数优化；限制深度、记忆、事件、非局域预算并保存 parent/new hash。
- 正向测试：等价重写保持类型、守恒 owner、适用域和 observable contract；重放 trace 得到相同结果。
- 反向测试：缺 condition、过时 manifest、跨单位/状态/账户的 rewrite、把 surrogate 排名当证据均拒绝。
- 退出门：搜索覆盖的只是声明 grammar 的可达空间；任何 `pass` 仍需 UP2、UP4、UP6 证据。
- 失败处理：把不可判定的 rewrite 记为 `unknown`，把预算耗尽记为 `deferred`，不发放永久 prune certificate。

### UP6：整装 R01–R10 的 G1 责任

- 输入：最终三 Genome candidate、独立 physics/engineering/control providers、VVUQ、证据 authority 和 replay 环境。
- 输出：G1 相关的独立验收包，供整装 R01–R10 汇总。
- 步骤：核对机制程序、守恒、适用域、可观测预测、逆向可达性、跨分辨率稳定性与独立重放；将 G1 结果与 G2 phenotype/G3 realization 分开归因。
- 正向测试：至少一个 candidate 通过适用的物理、工程、控制和独立验证硬门，并有 source/provider/scenario/uncertainty/independence receipt。
- 反向测试：只有局部 screen、合成数据、单一 basis、单次收敛或文档声明不得满足 R01–R10。
- 退出门：R01–R10 每一项都必须有逐项关账记录；声称某项不适用也必须由该项显式义务与 proof 关闭，不能忽略整个 R 项。只有全部关账才可更新 parent goal，否则 credible count 不得上调。
- 失败处理：按 `scientific fail`、`program exception`、`human interruption`、`not_executed`、`unknown` 和 `deferred` 分账并保留 match reason；`unsupported` 只能由最终 authority 依据证据签发。
