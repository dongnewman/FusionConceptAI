# 从当前断点到最终发现能力的执行路线

本路线不是“写完这些文档即完成”。每个阶段都要求代码入口、真实输入、实际运行和针对父需求的验收记录。旧代码优先做 extract/wrap/test-only/reject 复用审查；不移植旧 reference 特权、名称路由或低级 authority。

## 1. 主线与执行者

Sol high 负责物理建模、任务适用性、API/类型与方程设计、任务排序、源码合并、执行队列、独立审查及最终判定。Luna medium 负责有限文件范围内的具体实现、数据导入、测试、日志解析和只读复核。

最多同时三个 Luna：一个实现、一项独立数据/基准工作、一个审查或测试工作。主代理必须在派发前写好输入、输出、方程/不变量和反例。涉及新方程与闭合判断的任务先由 Sol 解决设计，不能让执行者自行删掉难项。

各工作单采用：`ID / parent_requirements / baseline / owned_files / input_artifacts / required_behavior / forbidden_shortcuts / commands / acceptance / output_paths / unresolved`。文件范围重叠时顺序执行；依赖未成熟的任务只写约定接口或独立工具，不凭空接线。

重型 Julia/DESC 由 Sol 串行排队。每个运行登记目的、冻结参数、超时/资源预算、PID、阶段日志、成功和失败退出码、恢复规则。预算用于防失控，不是降低科学门槛的理由。达到预算后保留失败，再按原因改变方法；不反复无理由扩大算量。

## 2. M0：固定总目标、接续基线、建立真正集成验收

依赖：无。父需求：R01、R10。

- 读取当前 HEAD/差异/进程和 [审计](01_audit.md)，重跑历史产物审计与近边界停滞复核。
- 建立最终需求账本和 capability/模型/数据缺口表；把此前已完成事项登记为局部里程碑，不清空父需求。
- 对 `src/FusionConceptAI.jl`、RuntimeV4 聚合器、example/runner、focused/test/runtests 的包含关系建立自动可读覆盖表。
- 给 RuntimeV4 建立稳定的可导入入口或正式、文档化的隔离入口，以及覆盖它的显式回归入口；避免把所有高成本 provider 强塞默认 unit suite。
- 区分快速 contract/numerics 测试、provider 集成、真实物理基准和终局验收。所有报告标出具体命令、revision、assertions、退出码和未覆盖范围。

交付：加载图、分层运行脚本、当前需求账本、失败复现记录；已有脏文件清单得到保留。通过后只能关闭 M0，不能关闭任何科学门。

## 3. M1：修复实际求解停滞并判断模型是否闭合

依赖：M0 的失败输入和执行规约。父需求：R03。

第一子任务精确针对 `SpatialMultiRegionV4.jl`：近零正压力不进入活跃集、可行步长近零、Armijo 舍入等目标接受。使用保存状态建立真实反例，再由 Sol 选择尺度一致的约束求解方法。可选方法需先分析：容差与 KKT 一致的活跃集、投影/约束优化、信赖域或 continuation；不得机械更换优化器而忽略方程不适定。

验收至少包含：真实下降与舍入无进展可区别；近零正压力、恰零、微负容差、不可行方向及驻点各有明确分类；新的实际尝试记录 state change、目标变化、KKT/梯度和退出原因。保持全部残差块、网格和容差要求。

第二子任务检查离散与物理闭合：逐区域未知量—方程—源/边界—接口—积分约束所有权；检查静态压力/电流拓扑未定、外牵引与外部磁场/电流是否兼容，零空间/非唯一、轴/周期约束及尺度。满列秩不能证明连续问题唯一。

第三子任务建立可独立求解的已知问题：不仅将解析场代入残差，还从不同初始化求回 MMS 解，至少三个分辨率或有充分理由的误差估计，包含非零源和边界。真实物理参考与 manufactured 数值验证分开。

交付：停滞修复、模型闭合报告、MMS 解恢复、真实基准的网格收敛及独立残差结果。原探索候选若仍失败，如实保留；可以诊断已知可解基准来区分 solver bug 与候选不相容，不能用那个基准的成功替换原失败结果。

## 4. M2：建立已知装置表示、真反演和留出预测

与 M1 数据工作并行；物理解算验收依赖 M1。父需求：R01、R02、R06。

- 建立来源登记：设计/实测/外部模拟、装置与工况、单位、版本、授权、文件哈希、误差、可用字段、不可公开字段及缺口。
- ITER 先做公开设计可表示性和 forward reference；不假设官方网页几个全局数值足以唯一恢复完整装置。
- 按 [B0–B3](02_acceptance_and_benchmarks.md) 实现导入/导出、真正参数反演、留出预测和 grammar 可达恢复。
- 至少一组实测基准支持 validation；再选择能力需求不同的第二参考，防止把最初后端适用域永久冻结成全项目搜索空间。
- 相同 mission/输入删除标签后必须沿同一物理路径。旧版 v102 reference 绕行及 applicability mismatch 作为反例。

交付：实际数据、adapter、inverse solver、frozen calibration/validation split、多初值轨迹、前向误差、可识别性、适用性与负例结果。只有有真实结果的 benchmark 可记 pass；缺数据的不是已完成。

## 5. M3：构建能算净输出的物理与工程纵链

父需求：R03–R05。先闭合最有依据的参考物理范围，再扩展其他 capability。具体模型由 Sol 根据候选机理与数据决定，不能用一个通用缩放公式替代全部装置。

| 生产模块 | 必须给下游的结果 | 验收关注点 |
|---|---|---|
| 约束场、平衡、轨道/损失和稳定性 | 状态/通量/稳定裕量与适用域 | 自洽来源，边界和外部线圈/回流；无家族 shortcut |
| 粒子/电子离子能量、反应/自加热、辐射与输运 | n/T/组分、反应率、损失和时间演化 | 守恒、刚性/时间/空间误差，数据校准和域外判断 |
| 实际实现、热与结构、材料和故障 | 可行实现、载荷、温度/应力/寿命/可控性 | 组件尺度/制造/供电/保护等可追溯；适用核工程与燃料义务不遗漏 |
| 能量转换与站级功率账本 | 周期净输出、负载拆分与守恒误差 | 无未知归零，无 Q 冒净电，无外部 ramp/储能赠能 |

每次补能力必须能从已执行上游消费真实结果，再被下一节点消费。若需要新增假设/模型/组件，写入 Genome/mission 的新版本、重新哈希并执行受影响链；不得将 solver 内部隐含项塞进旧候选。

这种数据接线只是必要条件。压力/电流↔平衡、n/T↔反应/自加热/输运、线圈/控制/温度↔场和实现状态等不可忽略反馈，必须在同一候选/场景下联立或分区迭代到预登记的接口、状态和守恒闭合容差。交付包含耦合迭代轨迹与所有反馈边误差；不能用单向后处理冒充完整耦合。one-way 近似只有在提供定量可忽略反作用依据和误差预算后，才能在对应有限作用域被接纳。

交付：同一参考候选从场到全装置功率的真实计算和独立审计；负净输出是允许的物理结果，但 R05 的“找到正净输出新候选”仍不满足。

## 6. M4：独立验证/UQ 与可晋升的 evidence 路径

验证数据获取、checker 和协议开发从 M2 即开始，最终接纳依赖 M3。父需求：R06、R07。

建立独立观测/代码来源、适用域和模型差异；区分 code verification、numerical verification、physical validation。概率模型必须有依据，参数相关性/模型误差不能只以独立 ±5% 扰动替代。

新增 additive 高等级 evidence 类型和最终 checker，保留旧 screen 类型上限。首个正通路使用真实可验证的基准证据，按其实际支持的等级通过；同源回放、跨候选、漏工况、伪造不确定性和缺工程义务的负通路必须拒绝。不要为了测试“能返回 true”生产虚假的物理高等级 evidence。

交付：可运行的等级判定、原始数据及独立重放、误差分解与传播、真实 benchmark 接纳记录、全部负例。若证据只够有限物理 scope，authority 只能接纳该 scope，不能当全装置 L4。

## 7. M5：搜索器尽早接入，评价器成熟后扩大

基础生成/档案开发可与 M1–M4 并行，不必等所有物理完成才写搜索器。大规模搜索及可信晋升必须等相关评价器与基准达标。父需求：R08、R09。

- 先用简单可解释生成器完成真实多代闭环：typed edit → 编译 → provider → 结果入档 → 下一代选择；同时做 B3 已知结构恢复。
- 补 G1 机制组合、G2 几何/场/拓扑和 G3 实现/控制编辑；同一 grammar 的可达空间、基函数/拓扑边界显式登记。
- 再落地多谱系 QD、渐进展开 MCTS、连续优化、多 emitter 与 dormant revival。每类预算与覆盖输出真实统计；不以改名/微扰刷候选数。
- 低保真 fail/不收敛/缺 provider 进入适当可恢复前沿；永久剪枝仍需范围明确的独立证明。
- 新机制没有适用 evaluator 时进入能力获取队列；不能因当前只有 DESC 就从 grammar 永久删掉非适用结构。
- 先做有界基准比较：随机/规则 baseline、typed generator、档案回写、多代重放；有明确收益或瓶颈后才扩大算量或复杂策略。
- 合格候选通过全链重算后，做外部文献/专利相似性与机制差异审查；把不成立的原创主张回写档案。

交付：冻结 seed/grammar/mission 的可恢复 campaign，多代实际轨迹、所有筛选原因、真实三 Genome 改变记录、原创性证据和局限。若结果数仍为 0，输出原因分布并继续最有信息量的能力/搜索改进；不得伪选“最接近”的 winner。

## 8. M6：最终独立验收

父需求：全部 R01–R10。

由未实施该模块的审查路径重放合格候选，检查训练/验证泄漏、净输出账本、适用硬门、范围变动、来源独立性、先例相似性和生成谱系。至少一个新候选满足全部门，才允许说原始发现目标在声明证据边界内达成。

每个源码里程碑经针对性 tests、实际 runner、受影响回归、独立 review 后单独提交；推送前核查远端和既有会话授权。不覆盖别人未提交文件、不 `git add -A`、不强推。文档完成或代理报告不替代源码与原始结果。

## 9. 停止无效劳动的规则

- 同一失败无新诊断时，不重复运行同一模型/seed/预算。
- 同一缺口反复输出合同但没有 producer、数据或诊断进展时，回到父需求找下一条可执行依赖。
- 每轮报告“新增了哪个真实能力、消除了哪个阻塞、基准和候选各通过几项”，不汇报文档数当物理进度。
- 外部数据/实验/算力确实不可得时，完成独立可做项，明确阻塞对象与最小所需输入；按实际 Goal 工具规则处理 blocked，不标 complete。
- 不预设最终科学发现的工期或保证结果。阶段预算要在实际命令执行前冻结，增加预算时记录依据和新版本。
