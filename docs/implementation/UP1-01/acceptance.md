## 实现范围

- `GrammarProfileV2.jl` 定义 candidate-owned additive operator spec、四轴 profile ref、provider match、typed units/time/effects/derivative budget 和 closure rule；并以版本化字段/约束 schema、canonicalization rules、applicability rules 计算可复算 SHA-256，不调用或修改 `default_operator_registry()`。
- `EquationPlanV2.jl` 定义 scalar 与真正的 2 输入/2 输出 MIMO equation plan。方程必须显式声明 role、operator ref、state refs、单位、时间语义、导数阶、effects、occurrences、closure ref 和 typed expression DAG（state/parameter/scalar-apply/MIMO-apply 节点及 roots）；MIMO roots 必须按输出端口顺序指向同一 MIMO apply，且多输入/多输出方程必须显式携带逐端口 input/output ranks，禁止默认 rank 掩盖端口错配；`g1_lowering_residual` 携带可消费 typed expression 与完整绑定。重复 occurrence、错误 root/port 在构造时 fail closed，纯文本 expression edit 被拒绝。
- `MechanismGenomePayloadV2.jl` 对完整 G1 内部 binding、state/plan/profile 做跨层 admission：binding 携带 URI、`v5` 合同 token、schema/canonicalization/grammar/applicability hash、compatibility profile、candidate binding 和四版本轴；要求各 hash 与当前版本化内容精确相等、governing/additive/constraint 三类角色、operator/profile 精确绑定、AST input physical type 与 payload state 完整一致、每个 equation 端口 unit/rank/temporal/derivative 一致、typed MIMO input/output roots、effect 集、closure ledger 与 balance 闭合；带 closure 的 equation 不得为空 occurrences。缺 hash、provider 或 schema/profile capability 时保留结构状态但 `terminal_deferred`，不进入 candidate-bound lowering/compile。`g1_materialize_contract_ref` 仅在四类 hash 与四轴均有效时生成真实公共 `GenomeContractRef`。
- `MechanismGenomeV5.jl` 对外只保存真实公共 `GenomeContractRef`，并要求其精确等于内部 binding 的 materialization；绑定四版本轴和 candidate hash。编辑单个 expression 会重建 plan/payload/Genome 并改变 plan hash 与 candidate hash。V1 payload/V4 Genome 入口明确拒绝原地重解释；pending binding 不能构造外层 Genome。
- fixture 的 states、operators、closures、equations、profile refs/limits 均由 `fixtures.json` 实际驱动构造；覆盖一个 governing、一个 additive、一个 2 输入/2 输出 MIMO constraint。负控覆盖 missing closure、duplicate effect occurrence、unit mismatch、legacy operator/version、wire-domain 旧 ref、provider no-match、pending hashes、version_axes mismatch、MIMO root node mismatch、MIMO output-port mismatch 和 MIMO input unit mismatch。
