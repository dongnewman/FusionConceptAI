## Blocking findings

1. **E0 source binding is incomplete.** `n06_projection_from_a` checks `e0.candidate_ref`, `e0.package_hash`, and that `e0.bound_input_hash` has type `Digest256`, then calls `up2e0_check_package(package)` (`:359-372`). It does not call the source-join validator `up2e0_validate_binding(e0, package)` or compare E0 outer refs, component hashes, and version axes with the actual package. A foreign or stale E0 object with the same candidate/package fields can therefore reach the projection. The baseline must be source-bound before any N06 projection or mutation result is admitted.

2. **G1/G2 selection still depends on order.** `_n06_actual_fields` sorts all governing occurrences and takes `[1]` (`:293-297`), and sorts candidate boundary patches and takes `[1]` (`:311-313`). This is an order-derived choice without a typed relation to the selected G3 role. The focused test helper repeats order/fixture selection with `occurrences[i]` and `boundary_matches[1]` (`test/GenomeV5/UP2/n06_source_field_ledger_mapping_tests.jl:76-115`). `_n06_index_for` is appropriate for deriving a path after an explicitly selected object, but it cannot justify selecting the object by sorted/index position. Require an explicit unique source predicate, or preserve the authority gap when no such relation exists.

3. **G1/G2 authority is not carried through the projection and mapping join.** `N06LedgerProjectionV1` stores G1 IDs/key and G2 region/face/locator (`:145-162`), but no typed G1/G2 source locator/ref/hash or actual source object identity. `n06_mapping_from_a` constructs a mapping from caller-supplied joins (`:508-521`); `_n06_join_errors` checks those joins directly against package collections (`:420-443`) but never requires them to equal the projection's selected G1 equation/occurrence/closure and G2 region/boundary. Thus a valid but different caller join can be internally consistent while disconnected from the projection. Mutation receipts contain only the selected G3 field locator/value (`:632-645`) and do not carry the G1/G2 source identity. This remains the R2 source-authority blocker.

4. **The selected flow link is not part of the join identity.** `_n06_actual_fields` chooses a flow port and a link targeting it (`:331-334`), but `N06SourceFieldLedgerJoinV1` has no link identifier and `_n06_join_errors` does not compare any caller join to the selected `link` or to projection field N06-03. It checks only that a caller `g3_port_id` exists and has the allowed role kind (`:444-458`). A caller can therefore provide a different valid flow/link relation and pass these local checks. The foreign-link test only exercises `_n06_unique_match` directly (`test/GenomeV5/UP2/n06_source_field_ledger_mapping_tests.jl:235-238`), not mapping admission. Add an exact selected-link identity or reject the mapping as unresolved.

5. **Mutation kind is not bound to the typed field.** `_n06_validate_spec_binding` binds id/path/locator/type but not `mutation_kind` (`:551-560`), while `_n06_mutate` dispatches on `spec.mutation_kind` alone (`:563-575`). A spec can retain a valid N06-01 id/path and substitute another registered mutation kind; the receipt then labels one field while mutating a different semantic value. Add an immutable field-path/mutation-kind registry and reject mismatched pairs. Fixture expected errors remain oracle-only.

The effort/flow dimensional checks themselves are now present, and the local law hash is correctly bounded as an internal contract hash. Those partial closures do not close the four source-binding blockers above. Existing absent/foreign partner controls are useful, but they cannot substitute for carrying the selected identities through the mapping.
