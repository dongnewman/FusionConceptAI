# UP1 external closure R2 — PKI chain verifier

Status: `accepted_limited` for a local software verifier and `TEST_ONLY` non-evidence fixtures; R1 and R2 attack-review rework is applied. This slice does not provide a production trust root, external attestor, revocation response, trusted signed time, or authority publication.

The verifier uses the installed Python `cryptography` package and does not install dependencies, contact the network, read a system trust store, or write trust state. It checks the deterministic receipt bytes and leaf signature, root self-signature and pinned-root semantics, issuer/subject and AKI/SKI links, validity, basic constraints/path length, key usage, attestation EKU, name constraints, policy OIDs, key algorithm/size, critical extensions, signer key id, scope/version and replay fields. Missing production root, profile, receipt, revocation or signed time is `typed_absence` → `terminal_deferred` with `no_publish=true`; invalid material is `fail_closed`.

The retained R2 test command exited 0 with twelve tests in `raw_fresh_r2/`; the latest R3 fresh command exited 0 with sixteen tests in a separate process (PID and UTC interval are recorded in `raw_fresh_r3/process.json`). The R1 attack findings are covered by regressions for RSA <2048, expired receipt/trusted-time windows, RFC822 domain boundaries, CA-only leaf keyUsage, unknown/duplicate JSON, and caller/profile/certificate TEST_ONLY mode mismatch. R2/R3 additionally cover closed algorithm values, RSA-SHA1/MD5/unknown rejection, per-certificate signature hash/OID binding, and profile/receipt algorithm mismatch. The generated certificate chain is explicitly `TEST_ONLY` and results are always `evidence_class=non_evidence` and `no_publish=true`. The production profile remains externally supplied and cannot use fixture OIDs or values by fallback.
