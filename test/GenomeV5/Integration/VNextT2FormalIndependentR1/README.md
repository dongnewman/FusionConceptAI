# VNext T2 independent formal negative coverage

This leaf is an independent successor test plan for the formal T2 consumer
boundary. It does not modify the product modules or the implementation-owned
positive controller. The accepted V3 software qualification and T1 software
manifest are upstream authorities; every Julia execution still requires the
root coordinator's serialized lane grant.

The formal run has three deliberately separate evidence domains:

1. `actual_formal_matrix`: consumes the accepted T1 software manifest and the
   producer's original `candidate_package.jls`, rebuilds the expected T1
   admission once, creates an actual formal gate, commits one positive five-
   consumer ledger, and attacks that immutable baseline.  Rejections record
   observations before assertions and prove the caller package and prior
   ledger remain unchanged.
2. `artifact_and_driver_boundaries`: exercises raw package hash and
   deserialization preconditions, the candidate-receipt authority precondition,
   and the serialized-result and stable-projection output postconditions.  A
   precondition failure must attempt no T2 consumer.  A postcondition failure
   retains the real attempted trace but publishes no final artifact.
3. `supplementary_contract`: preserves the old synthetic-local assertions that
   do not represent an actual formal gate, including edited-operation deferral.
   These results cannot qualify the formal manifest by themselves.

The implementation-owned driver is also invoked directly for damaged producer
artifacts, candidate-receipt rejection, serialized-result and stable-projection
postconditions, and occupied output targets. Raw-hash rejection, real
deserialization failure, a serialized wrong type, and a valid foreign package
are separate cases. Precondition failures require zero consumers; output
postcondition failures retain all five attempted and in-process committed
receipts while publishing no final artifact.

`build_coverage_map_r1.py` freezes the old focused-suite assertion sites and
maps all 154 lexical sites and 174 old dynamic hits to concrete successor
assertions. The successor freezes 191 Julia assertion sites, 530 planned
assertion hits, 60 unique semantic cases, and 68 planned case executions.
Runtime multiplicity is separate from
lexical ownership: the five N10 rows, two corrupt-deserializer helpers, two
synthetic-boundary observations, and seven occupied-target executions are
recorded explicitly.

`coverage_ast_inventory_r1.jl` parses the immutable 154-site suite, the
191-site successor, and the 24-site projection regression without loading a
fixture or product module. It records the exact raw Julia AST hash and a second
hash that removes only `LineNumberNode`, together with each site's enclosing
testset, function, loop, and conditional context. The 369 parsed rows remain
separate from semantic runtime multiplicity and bind the old-to-new mapping by
site ID. Each enclosing control node also records its AST path and child index
plus raw and semantic context hashes, so iterator, condition, and branch
placement remain visible.

`freeze_independent_negative_protocol_r1.py` can freeze the final protocol only
after the implementation-owned positive producer/replay has passed. It pins
that positive evidence, its full runtime closure, this suite, the historical
focused suite, and the review inputs. The runtime parser checks every pinned
Julia source before any product execution; the Python static QA checks the
coverage and command without creating bytecode.

No scientific, physical, provider, solver, search, or R01-R10 acceptance is
claimed by this suite.
